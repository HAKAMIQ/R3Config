# discord-bot audit corpus

Machine-readable dispositions for the discord-bot reference (LGPL-2.1; nothing copied, only facts: line references, key names, serial sets, counts).
Generated by a dev-time script from the local snapshot; gated by `Tst/DiscordBotAuditT.cs` (R3Test).

| File | Content |
|---|---|
| `regex-coverage.json` | all 188 GeneratedRegex patterns: disposition, real-log hits, RPCS3-source literal, implementing symbol, rationale |
| `general-notes-rules.json` | every GeneralNotes emission (112): severity, input keys, version constants, settings referenced, disposition. No advice sentence is stored |
| `weird-settings-rules.json` | every WeirdSettings emission (216), same shape |
| `weird-settings-families.json` | 33 game-family serial sets (exact product codes), the rules that use them, Wiki/catalog serial coverage, classification |
| `subsystems.json` | every bot subsystem and lesson with a disposition |
| `summary.json` | recomputable counts |

Dispositions: regex `ALREADY_COVERED | IMPLEMENTED | QUEUED_FIXTURE | REFERENCE_ONLY | SUPERSEDED | NOT_APPLICABLE`;
notes `ALREADY_COVERED | IMPLEMENTED | REFERENCE_ONLY_CURRENTLY_UNVERIFIED | SUPERSEDED_BY_CURRENT_EVIDENCE | NOT_APPLICABLE`;
families `OFFICIAL_CURRENT | CORROBORATED_NON_OFFICIAL | REFERENCE_ONLY | SUPERSEDED | CONFLICT | OBSOLETE`.
Note-rule dispositions are derived from the input keys the rule reads: an "IMPLEMENTED" rule means the OBSERVED FACT it depends on is stated by the
parser; the advice attached to it is not ported. Game-family rules are all `REFERENCE_ONLY`: no predicate-level comparison against the Wiki has been made,
so none is an active finding, and none expands serials fuzzily or inherits across editions.
