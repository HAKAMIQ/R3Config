# تحديث قاعدة التوصيات (Recommendation Sync)

يحدّث R3Config قاعدة التوصيات من مصادر RPCS3 الرسمية ويحفظ التحديثات في طبقة محلية فوق القاعدة المدمجة.
المزامنة تقرأ الشبكة وتكتب مخزنها الخاص فقط؛ لا تفتح أي ملف RPCS3 ولا تطبق أي توصية على لعبة.

## المسار

```text
api.rpcs3.net/config (JSON + RPCS3 YAML)      wiki.rpcs3.net/api.php (MediaWiki)      GitHub master/r3config-data
  -> ConfigApiParser                            -> WikiRevisionSource -> WikiSvc.ParseLivePages       -> GitHubRecDataSource
  -> RecSyncMerge.ApplyConfigApi                -> RecSyncMerge.ApplyWikiPages                        -> manifest + payloads
                \                                /                                                          /
                 RecSyncService (قفل واحد، حالة مستقلة لكل مصدر)
                 -> RecSyncStore (%LOCALAPPDATA%\R3Config\RecSync)
  -> RecommendationSyncUseCase -> AppFlow -> MainVm (Main.Sync.cs) -> RecSyncVm -> View/ARecSync.xaml
  -> RecSyncMerge.BuildEffective(cat.json, store) = الكتالوج الفعلي وملاحظات عربية في الذاكرة
```

- `App/Data/cat.json` يبقى Baseline للقراءة فقط ولا يُعدَّل. عند توفر حزمة GitHub سليمة تصبح قاعدة العرض المحلية، ثم تضاف
  فوقها صفحات الويكي الأحدث وحالات Config API المؤكدة؛ وتبقى الحزمة المقبولة في مخزن Last Known Good المحلي.
  لا تُكرر الإعدادات (مفتاح واحد لكل Serial/Section/Key)، ولا تُحدد توصيات GitHub تلقائيا.
- قراءة الطبقة المحلية عند تحميل الكتالوج محلية فقط. أول فحص شبكي بعد 30 ثانية من ظهور النافذة، ثم فحص كل ساعة
  ينفّذ المزامنة إذا مرت 24 ساعة على آخر محاولة. `RecSyncService` يمنع تشغيل مزامنتين معًا (`AlreadyRunning`).
- متغير البيئة `R3CONFIG_DISABLE_AUTO_SYNC=1` يوقف كل طلب تلقائي (يضبطه `R3Test`). الفحص اليدوي يبقى بمبادرة المستخدم.

## المصادر ودلالاتها

| المصدر | ما يقدمه | ما لا يقدمه |
|---|---|---|
| Config API (`api=v1`) | لقطة كاملة لكل Serial: إعدادات RPCS3 بأسمائها وقيمها الفعلية | الملاحظات، فئة Mandatory، نطاق Serial داخل صفحة الويكي، إعدادات مثل `Minimum Scalable Dimension` و`Resolution Scale` و`Net` |
| Wiki (MediaWiki) | نص الصفحة الأحدث يُحلَّل بالمحلل والخريطة نفسيهما المستخدمين لـ cat.json | — (محجوب حاليًا بتحدي Cloudflare) |
| GitHub (`HAKAMIQ/rpcs3/master/r3config-data`) | التوصيات وملاحظات Wiki العربية بعد التحقق من المخطط والإصدار والحجم وSHA-256 | التطبيق لا يعدل Fork ولا يرفع إليه بيانات |

مقارنة 2026-10-20: 2236 Serial مشتركًا، 4722 قيمة متطابقة و0 تعارض قيم، 383 قيمة في API فقط، 975 قيمة في القاعدة فقط.
لذلك غياب قيمة من API **ليس** حذفًا، وقيمة API لـ Serial غير Primary أو مستبعد بنطاق الويكي لا تُطبَّق.

## المقارنة مع RPCS3 الرسمي (`config_database.cpp`)

RPCS3 يقرأ `https://api.rpcs3.net/config/?api=v1`: JSON كائن، `return_code` رقمي (غيابه = -255، السالب خطأ)، `games` كائن،
ولكل Serial كائن فيه `config` نصي يُتحقق منه بـ `cfg_root::validate` (YAML صارم: أي مفتاح مجهول أو قيمة غير صالحة لهذا
الإصدار من RPCS3 تُسقط إعدادات اللعبة كاملة). بعد نجاح القراءة يكتب الرد كما هو إلى `GuiConfigs/config_database.dat`
تحت مجلد بيانات RPCS3 (`portable` ثم `RPCS3_CONFIG_DIR` ثم مجلد التنفيذ)، ويقرأ هذا الملف عند التشغيل دون اتصال.
RPCS3 يحوّل `\` في `RPCS3_CONFIG_DIR` إلى `/` ويقطع القيمة بعد آخر فاصل، فالقيمة `C:\cfg\` تعني `C:\cfg` بينما
`C:\cfg` بلا فاصل أخير تعني `C:\`. R3Config يطبق القاعدة نفسها في تحديد مجلد البيانات (`GuiConfigs` و`config/custom_configs`).

| النقطة | RPCS3 | R3Config |
|---|---|---|
| `return_code` | يقبل أي قيمة >= 0 | يقبل 0 فقط (أشد؛ الرفض يُبقي آخر نسخة سليمة) |
| `timestamp` | يُتجاهل | مطلوب، وهو وقت التصدير: رد أقدم من اللقطة المقبولة يُرفض (`Invalid`) ولا يُرجع التوصيات |
| مفاتيح JSON المكررة | آخر قيمة | يُرفض الرد |
| اللعبة غير الصالحة | تُتجاهل | تُتجاهل وتحتفظ بحالتها السابقة؛ أكثر من 5% = رفض الرد |
| YAML | yaml-cpp + `cfg_root` للإصدار المثبت | قواعد نحوية محدودة ثم تحقق لكل إعداد على حدة (خريطة R3Config ومجالات القيم) |

R3Config لا يملك `cfg_root` للإصدار المثبت، لذلك لا يحكم على صلاحية اللعبة كاملة بحسب الإصدار. مثال 2026-10-20: الإصدار
`v0.0.43-20204-c673da45` لا يعرف `SPU MMIO Delay Enabled` و`Emulate BD-ROM Read Speed`، فيرفض RPCS3 إعدادات 21 لعبة كاملة.
المفتاحان خارج خريطة R3Config (`UnsupportedSetting`) فلا يُكتبان أبدًا، ولهذا لا يطبق R3Config بقية إعدادات تلك الألعاب منفردة:
كل لعبة يحمل ردها إعدادًا خارج الخريطة تُعد متوافقة جزئيًا (`RecSyncReason.PartialConfig`)، فتُحجز قيمها المدعومة في Quarantine
للمراجعة وتُسقط تعديلات API السابقة لها فتعود إلى القاعدة المدمجة. اللعبة التي يصبح ردها كاملًا تُقارن كأنها جديدة.
في 2026-10-20 كانت 55 لعبة متوافقة جزئيًا، منها 9 كانت تحمل `Write Color Buffers` مطبقًا بدون `Emulate HDD Read Speed`.

### نسخة RPCS3 المحلية

`ConfigApiParser.LocalDatabasePath` يحدد `GuiConfigs/config_database.dat` من مجلد بيانات التثبيت المحدد. الملف يُقرأ فقط
(`FileShare.ReadWrite`) ولا يُكتب، ولا يُستخدم إلا إذا فشل الطلب الرسمي (شبكة، حجب، 429، رد مرفوض)، وبصمته SHA-256 تختلف
عن اللقطة المقبولة، و`timestamp` فيه أحدث تمامًا منها. يمر بالمحلل والدمج وحد الإزالة نفسها، ويبقى المصدر معلنًا كفاشل مع
موعد إعادة المحاولة. نجاح الطلب الرسمي يتجاهل الملف. لأن RPCS3 يكتب الرد كما هو، تطابق البصمة يعني الرد نفسه، فلا يُعاد
تحليله. الخادم لا يرسل ETag/Last-Modified، لذا يبقى الفحص طلبًا كاملًا كل 24 ساعة يُتجاهل إن لم تتغير البصمة.

## قواعد الدمج

- أول مصالحة مع Baseline: تُضاف فقط قيمة مدعومة وصالحة لـ Serial معروف `Primary` لم تكن لديه القيمة، ولا تحمل صفحته
  هذا الإعداد لنسخ أخرى (`ScopeExcluded`). القيمة المختلفة عن Baseline = `BaselineConflict` للمراجعة. الغياب لا يُحذف.
- بعد ذلك يُقارَن كل رد كامل بالرد المقبول السابق: إضافة/تعديل/إزالة مؤكدة بين ردين كاملين تُطبَّق. الإزالة تُسجَّل
  كـ Tombstone فقط إذا كانت قيمة Baseline هي القيمة التي أزالها المصدر.
- لعبة قرأ API إعداداتها بشكل تالف تُعامل كمجهولة لهذه الدورة وتحتفظ بحالتها السابقة. رد أقل من 100 لعبة، أو أكثر من 5% تالف،
  أو يزيل أكثر من max(50، 5% من الإعدادات) دفعة واحدة يُرفض كاملًا وتبقى آخر نسخة سليمة.
- القيم من مجالات متحقق منها فقط: مجموعات قيم محلل الويكي، Boolean، نوع القيمة الافتراضية في RPCS3، أو صيغة `<lib>.sprx:lle`.
  الإعدادات خارج الخريطة (مثل `VFS`) = `UnsupportedSetting`، وبقية قيم اللعبة نفسها = `PartialConfig` ولا تُطبق.
- Serial جديد من API بلا هوية مثبتة (عنوان وصفحة) = `UnknownSerial`. إضافة لعبة جديدة تأتي من صفحة ويكي فقط.
- تعديل نصي في صفحة ويكي لا يغيّر الإعدادات المستخرجة لا يُسجَّل (Semantic Diff عبر المحلل نفسه).
- إذا غيّر المصدران الإعداد نفسه بقيمتين مختلفتين = `SourceConflict` وتبقى قيمة Baseline.
- كل ما لم يُطبَّق يظهر في Quarantine مع السبب ولا يطبق تلقائيًا.

## التطبيق على الألعاب

التوصيات المحدّثة تحمل الأصل `RecOrigin.Sync`. `StateSvc` لا يجعلها قابلة للاختيار التلقائي أبدًا (`Manual`)، وتظهر في
خطة الإعدادات عند الفحص التالي. التطبيق يمر بالمسار الحالي فقط: Preview ثم `IRpcs3MutationGuard` ثم نسخة احتياطية ثم
Rollback عند الفشل، وبعد موافقة المستخدم.

## الشبكة

- `RecSyncHttp`: HTTPS إلى `api.rpcs3.net` و`wiki.rpcs3.net` و`raw.githubusercontent.com` فقط، بلا Redirect أو Cookies، مهلة 30 ثانية للمحاولة،
  حد حجم (8MB للـ API والتوصيات، 16MB للويكي، 1MB للملاحظات، و64KB للـ manifest)، ثلاث محاولات للأخطاء العابرة. 403/صفحة HTML = `Blocked` بلا إعادة ومحاولة
  بعد 24 ساعة؛ 429 يحترم Retry-After حتى في الفحص اليدوي؛ ETag/Last-Modified يُرسلان إن وُجدا. لا يُرسل أي Serial
  أو قائمة ألعاب أو بيانات مستخدم.
- `WikiRevisionSource`: recentchanges (namespace 0، `continue`، `maxlag=5`) من watermark ناقص نافذة تداخل 6 ساعات، وإزالة
  تكرار المراجعات المعالجة، ثم revisions (`rvslots=main`) بدفعات 50. watermark أقدم من 80 يومًا أو قائمة طويلة جدًا =
  مصالحة شاملة عبر `embeddedin` لـ `Template:Config`. يحفظ watermark والمراجعات المعالجة فقط بعد نجاح الدفعة كلها.
- في 2026-10-20: Config API يعمل (200، 2287 لعبة، بلا ETag/Last-Modified)، والويكي يرد 403 بتحدي Cloudflare. لا يُتجاوز
  التحدي؛ مصدر الويكي يبقى `Blocked` وتبقى بياناته السابقة، ويعمل تلقائيًا إذا أُتيح وصول رسمي.
- يُحمّل GitHub من روابط ثابتة في `master`. إذا كان manifest غير منشور (404)، تظهر حالة «قاعدة GitHub لم تُنشر بعد» وتبقى آخر نسخة سليمة.

## التخزين والتعافي

`RecSyncStore`: `store.json` + `store.lkg.json` (آخر نسخة سليمة) + `prefs.json`. الكتابة إلى ملف مؤقت ثم استبدال واحد.
ملف تالف يُنحّى (`store.json.corrupt-*`) ويُستعاد LKG؛ إن تلف الاثنان تُستخدم القاعدة المدمجة وحدها. مخطط أحدث من
البرنامج لا يُقرأ ولا يُكتب فوقه. الإلغاء قبل الحفظ لا يغيّر شيئًا. ترقية cat.json (بصمة مختلفة) تزيل من الطبقة ما صار في
القاعدة الجديدة وتعيد قراءة API كاملًا. تفضيلات تالفة = إيقاف التحديث التلقائي (Fail closed).

## الواجهة

الأدوات المتقدمة ← تحديث التوصيات: تفعيل التحديث التلقائي (افتراضيًا مفعل؛ إيقافه يوقف كل طلب تلقائي)، إشعارات مهمة لألعابي
فقط (افتراضيًا صامت؛ سطر في شريط الحالة لا Dialog ولا Toast، ولا يتكرر للمراجعة نفسها)، فحص الآن، آخر فحص ناجح، حالة كل
مصدر، الأعداد، وسجل التغييرات (القديم/الجديد/الحالة/رابط المصدر).

## الاختبار

`R3Test.exe --rec-sync-only` يشغل `RecSyncT` (ضمن RelTest أيضًا) بمعالج HTTP مزيف وfixtures في `Tst/Fixtures/RecSync`،
ومنه رفض الرد الأقدم ونسخة RPCS3 المحلية (أقدم/بالوقت نفسه/تالفة/أحدث، قراءة فقط تحت قفل يمنع الكتابة، دون شبكة،
أثناء Backoff حيث لا يُرسل طلب ولا تُقرأ النسخة، وأثناء كتابة RPCS3 لها أو قفلها حصريًا)، والإعدادات المتوافقة جزئيًا،
وتفسير `RPCS3_CONFIG_DIR` بالفاصل الأخير وبدونه مع أولوية `portable`.
`R3Test.exe --rec-sync-live <dir>` فحص حقيقي إلى مخزن مؤقت، خارج بوابة الإصدار. `UiGate` يعرض الصفحة بالعربية والإنجليزية
والثيمين بأحجام وDPI متعددة.
