# RPCS3 integration audit — retained Artemis scope

The retained Artemis path is intentionally narrow: R3Config consumes the ChiDreams RPCS3 patch collection as ordinary RPCS3 patch definitions. It does not provide a second Artemis engine.

## Production boundary

```text
App/Data/art.yml
 -> PatchCatalogUseCase
 -> PatchCompatibilityService
 -> explicit selection
 -> BundledCheatPatchService
 -> managed title-specific patch YAML + patch_config.yml
```

RPCS3 remains the component that interprets and applies RPCS3 patch YAML. R3Config only prepares and manages those files while RPCS3 is closed, using existing mutation guards and backup/rollback behavior.

## Identity boundary

The patch catalog may contain PPU, SPU, PRX, or OVL executable keys generated by RPCS3. The existing generic `RunKey`/hash compatibility logic validates those keys. That generic patch identity contract remains because it is required by ordinary RPCS3 patch matching; it is not a direct-memory Artemis feature.

## Removed scope

No direct guest-memory writer, background reapply loop, separate Artemis reference database, raw PS3 cheat-program parser/executor, community evidence adapter, or alternate execution fallback is part of the retained integration.
